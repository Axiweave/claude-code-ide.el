#+TITLE: Open Issues

Known problems that have no fix yet. Each item names its spec entry, which has the evidence.

* Worktree ([[file:specs/016-worktree-audit/invariants.md][specs/016]])

** TODO R6: Concurrent operations on one repository are not serialized
Nothing serializes two operations on the same host and repository. Git locks each ref and index write. Each step re-checks its captured refs and Worktree before it runs. A clash probably fails a step and ends =unknown=. This is not verified.
- Upgrade path: a =mkdir= lock per repository common dir in the runner admission.

** TODO M2: Native move capture depends on Magit internals
=--capture-native= depends on the statement order inside =magit-worktree-move=. It does not advise =expand-file-name= or =file-exists-p=. A Magit change can capture the wrong argv or fail.

** TODO L5: A retry after an Agent switch has an unclear refusal
=--retry-ready= reuses the old =:launch=. =--launch-current-p= rejects it. The user sees only "The operation changed during confirmation".

** TODO R7: A TOCTOU window on the bootstrap name (uncertain)
See =remote-worktree-runner.sh:1014-1022=. It needs a second writer in the private directory, which has mode 0700.

** TODO R8: A truncated diagnostic has no marker
The runner sends at most 64 KiB of a diagnostic and does not say that it cut the text.

** TODO R9: Raw bytes in a diagnostic are not cleaned
The diagnostic decode and =--display-text= keep raw bytes above =#x10ffff=.

** TODO M3: Push-suffix advice uses cached interactive forms
The package reads the interactive forms once at load time. It does not see a later redefinition of a suffix.

** TODO M4: The confirmation deferral has no upper bound
The confirmation waits for the user with no timeout. The approval signature check still stops a stale plan.

** TODO L6: Retained operations are never pruned
=--operations= keeps every result until Emacs exits. =docs/remote.org= documents this.

** TODO L7: =--fail= does not clear =request=, and =--release= has no guard
No failure path depends on either today.

** TODO G3: The repository scope does not refresh local branch metadata
Only the global scope refreshes it (=manager.el:2411=).

** TODO G4: The Session directory may not follow a remote move (uncertain)
Not reproduced.

** TODO PF1: The wt merge reads run one after the other
=--prepare-merge= reads the merge target, then the merge settings. The reads are independent. A parallel read saves one remote round trip.

** TODO PF2: Postcondition reads run one after the other
=--read-extra-conditions= sends each read after the previous one. The reads are async, so the UI does not block.

* Attached-editor handoff ([[file:specs/010-attached-editor-handoff/invariants.md][specs/010]])

** TODO Z1: zmx drops answer packets from a client that is not the input leader
zmx forwards input from such a client only when =util.isUserInput= passes. An APC-only =pi:editor-*= answer does not pass. The Agent then stays pending.
- Upgrade path: add a key that passes the gate to each answer, or let zmx forward =pi:= APC input.

** TODO A6: The 500 ms ack window is too short for a busy Emacs
Ghostel runs the handler on the main thread. A main thread that is busy for more than 500 ms misses the window.

** TODO A7: The Agent abandons a file that Emacs accepted late
After a late ack, the Agent opens =$EDITOR= and deletes the file when that editor exits. The Emacs =done= then has a stale id.
- Upgrade path (A6, A7): a longer window with an explicit decline from Emacs, or an Agent → Emacs abort before the fallback.

** TODO E5: The answer goes to a dead Session buffer after a reattach
The request keeps the buffer object from the accept time.
- Upgrade path: find the current Session buffer by Session id when the answer is sent.

** TODO E1: The user =C-g= wrapper also sends the marker in copy mode
=leo/claude-code-ide-session-send-ctrl-g= in the user config calls =claude-code-ide-session-send-control-g= in every Ghostel mode.

** TODO A10: Nested tmux drops the editor request
tmux 3.3 and later drop the =DCS tmux;= wrapper unless =allow-passthrough on= is set.

* Remote Magit companion ([[file:docs/remote.org][docs/remote.org]], "Repair and lifetime rules")

** TODO MG1: The tramp-rpc Magit prefetch lists every ignored file
tramp-rpc has a Magit prefetch (=tramp-rpc-magit.el=). After =git update-index --refresh= exits 0, it sends about 87 git commands in one =commands.run_parallel= call and serves Magit from the results (=tramp-rpc.el:2264-2280=). One of these commands is =git ls-files -z --full-name --others --ignored --exclude-standard= (=tramp-rpc-magit.el:390=). It lists every ignored file in the working tree.
- ramhorn =~/SAGA-sdk= (626 GB, mostly ignored): this command takes 17.2 s and prints 624 MB. Every status refresh of that repo takes about 17 s. Without this command, a refresh takes 0.5-0.8 s.
- My first probe charged the 17 s to =update-index --refresh=, because the prefetch runs inside that =process-file= call. It is not racy git.
- The prefetch runs only when =update-index --refresh= exits 0. It exits 1 when tracked files have changes, as in both v12mac Agent worktrees (113 and 134 changed files). There the prefetch is skipped, and a refresh takes 0.6-0.8 s with 37 RPC calls. With the prefetch forced, even without =--ignored=, a refresh took 1.5-1.7 s. The v12mac prefetch also sent 3 file-metadata batches (517 entries) and moved 18.9 MB, 16.9 MB of it from the =--ignored= listing.
- Intent (7e0d529 message and the comment at =tramp-rpc-magit.el:385-387=): prefetch the git calls of Magit's lazy file-list sections (=magit-insert-ignored-files=, =-tracked-files=, =-skip-worktree-files=, =-assume-unchanged-files=), so TAB on them uses the snapshot.
- The cache key is the exact argv (=tramp-rpc-magit--process-cache-key=). The 5 prefetched =ls-files -z --full-name ...= commands (lines 388-392) never match. Magit sends =ls-files -z --others --ignored --exclude-standard=, and the ignored section adds =--directory= (recorded live, =magit-git.el:1160-1278=, =magit-status.el:828=). No Magit call passes =--full-name=. So these 5 commands run on every clean-tree refresh, and their results are never used.
- The user status hook has none of these sections.
- Upstream =origin/HEAD= (9ca02be) still has the commands. They came in with 7e0d529 "perf: speed remote Magit status expansion" (2026-06-25). No upstream issue mentions them.
- Upgrade path: upstream, remove the 5 entries, or use Magit's argv (=--directory= for the ignored section). As a local fix, a =:filter-return= advice on =tramp-rpc-magit--prefetch-git-commands= can drop them, but that function is private.
- Local workaround (user config, =lisp/init-tramp.el=): =leo/tramp-rpc-magit-drop-full-name-prefetch= removes the 5 entries. Measured live: 87 to 82 prefetch commands, and a ramhorn =SAGA-sdk= refresh went from 17.3 s to 0.37-0.45 s. Keep this item open until upstream fixes the entries, then remove the advice.

** TODO MG3: =remote-worktree-bootstrap-requires-owned-execution= is flaky under load
It failed in 2 full suites (the second while testing the pin-order editor fix, which does not touch Worktree code). Each time it passed 3 of 3 times alone. It uses real shells with =sleep= and a background =attach=.

* Emacs performance (live profiler reports, 2026-09-29)

These items stay open after the 2026-09-29 fixes. Those fixes removed the Spacemacs frame title (5.5% CPU), the per-dispatch tramp-rpc version check (3-7% of allocation), the =format-spec= call in the ghostel title (3.2% CPU), =locate-library= in the =use-package= =:ensure= advice (41.9% CPU in one profile), and the =better-jumper= data in saved cc-manager layouts.

** TODO PR1: =ghostel--pixel-anchor= costs about 5% of CPU samples
Each ghostel redraw calls =window-text-pixel-size= from =ghostel--pixel-anchor= (=site-lisp/ghostel/lisp/ghostel.el:4820=). It was 4.5% self in the 03:41 profile and 4.8% (434 of 9115 samples) after the fixes. The cost is Emacs layout, not Lisp.
- A live probe counted 265 calls in 20 s. Only 47 (18%) had the same buffer tick, window size, target, and window start as the previous call. A cache on these inputs would save little.
- =ghostel-window-padding-balance= is =top=, so the loop over the other windows does not run.
- Upgrade path: skip anchors while output streams faster than the display can show, or measure fewer lines.

** TODO PR2: claude-code-ide always runs uncompiled
=scripts/compile-and-test.sh= deletes all =.elc= and =.eln= files after each run. Emacs loads the =.el= files, and native compilation never starts, because it needs an =.elc= file. The hot functions =claude-code-ide-manager--save-state= and =claude-code-ide-session-idle--filter-advice= run in the interpreter.
- Upgrade path: keep the =.elc= files after the test run, or compile to a separate directory. =load-prefer-newer= is now =t= in the dotfiles, so an edited =.el= file wins over an older =.elc= file.

** TODO PR3: Old saved layouts keep their =better-jumper= data until the next capture
The capture now binds =window-persistent-parameters= to the side-window parameters only. The 20 layouts saved before this fix still have the jump history, so the state file is 275 KB. It was 717 KB before the fix. =persist-save= was still 48 of 9115 samples and 33 MB in a 30 s profile.
- A layout gets smaller when the Session switches and the manager captures it again. Layouts that the manager never captures again stay large until the 20-layout cap drops them.

** TODO PR4: Each =process-live-p= on an =/rpc:= connection goes through two file-handler dispatches
tramp.el builds the =process-status= advice at run time (=tramp-add-external-operation=, =tramp.el:2633=), so the advice is an uncompiled lambda. Each call runs =find-file-name-handler=, then =tramp-rpc-file-name-handler=, then =tramp-rpc-handle-process-status=, then =tramp-run-real-handler=. =process-status= was 8.6% inclusive of CPU in the 03:41 profile. =file-remote-p=, =tramp-connectable-p=, and =tramp-get-connection-property= start these calls.
- The profile keeps 16 frames, so it does not show the callers above them.
- Next step: set =profiler-max-stack-depth= to 64 and profile again to find the callers.

** TODO PR5: Garbage collection pauses average 162 ms
100 collections took 16.2 s in 14.4 min of uptime (=gc-cons-threshold= 100 MB, =gc-cons-percentage= 0.1). "Automatic GC" was 7.6% of CPU samples.
- A lower threshold does not make each pause shorter. The mark phase scans all live data, so it gives more pauses of about the same length.
- Upgrade path: allocate less. In the 03:50 memory profile, the largest allocators that these fixes do not touch are =accept-process-output= (12%) and =completing-read-default= (6%, in the Spacemacs help browser).
