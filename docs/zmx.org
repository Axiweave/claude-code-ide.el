#+title: Persistent Sessions with zmx
#+options: toc:2 num:nil

* Purpose

The optional zmx integration makes zmx the owner of each local Agent process.
Emacs becomes one attach client, so the Agent can survive buffer kills, connection loss, and Emacs restarts.

Use this guide for local persistent Sessions.
For Sessions on another host, see [[file:remote.org][Remote Agents and Project Views]].

* Requirements

Install [[https://github.com/neurosnap/zmx][zmx]] and make its executable available to Emacs.
This package has verified ordinary attachment with stock zmx 0.7.1 and 0.8.0.
The remote image route has verified input-owner queries and mode 5522 replay with stock zmx 0.8.1.
Stock zmx 0.8.1 can discard large input when its PTY queue fills.
The remote image route also needs lossless input backpressure on every host that runs the Agent.
The private =0.8.1-cci014-backpressure= candidate passed the [[file:../specs/014-remote-image-paste/quickstart.md][live acceptance checks]] on macOS ARM64.
The same source, built for Linux x86_64 (static musl), passed the nine =test/backpressure.py= cases on =v12dev=.
It is installed on =v12mac= and =v12dev=.
A host that still runs stock zmx keeps the large-input loss.

Enable persistent Sessions:

#+begin_src emacs-lisp
(setq claude-code-ide-use-zmx t)
#+end_src

Set these options only when the defaults do not match your system:

#+begin_src emacs-lisp
(setq claude-code-ide-zmx-program "/path/to/zmx"
      claude-code-ide-zmx-session-prefix "cci-")
#+end_src

The integration remains disabled by default.
A missing executable produces a user error only when a zmx operation starts.

* Start and Reattach

Start an Agent with the normal Claude Code IDE command.
The package wraps the Agent command as =zmx attach NAME COMMAND...=.
Generated names use =PREFIX-AGENT-PROJECT-ID= components, with =cci-= as the default prefix.

A normal start offers matching zmx Sessions not already attached in this Emacs.
You can select an existing Session or select =Create new session=.
Continue and resume offer only matching Sessions with zero attached clients.
They create a new Session when no such Session exists.

The package also adopts Sessions that another terminal or Emacs created:

- =M-x claude-code-ide-attach= selects one Session.
- =M-x claude-code-ide-attach-all= adopts all usable Sessions.
- =M-x claude-code-ide-attach-select= opens a marked-selection buffer.

The marked-selection buffer uses these keys:

| Key | Action |
|-----+--------|
| =m= | Mark the current row. |
| =u= | Unmark the current row. |
| =SPC= | Toggle the current row. |
| =t= | Invert all marks. |
| =C-c C-c= | Attach marked rows. |
| =C-c C-k= or =q= | Cancel. |

Bulk attachment skips Sessions without a start directory or a recognized Agent command.
The result message names skipped Sessions.
Use individual attachment to supply missing information interactively.

* Use Another Terminal

Run =M-x claude-code-ide-copy-zmx-name= to copy the current zmx name.
Then attach from a terminal:

#+begin_src sh
env -u ZMX_SESSION -u ZMX_SESSION_PREFIX zmx attach NAME false
#+end_src

Multiple clients can attach to one zmx Session.
Input and output belong to the same Agent process.

** Remote Image Input Ownership

Remote OMP image paste requires the intended Emacs attachment to own zmx input.
Each new remote attachment carries a unique =CLAUDE_CODE_IDE_CLIENT= marker.
The package adds that marker to =ZMX_TRACK_ENV= after the login profile runs.
It preserves the effective tracking list, including an explicitly empty list.
When the list is unset, it retains the stock 0.8.1 defaults.
The package stores its marker on the local attachment process, not in persisted Session data.

Before image transmission, the package queries =zmx print-env NAME CLAUDE_CODE_IDE_CLIENT= through the existing SSH control path.
A mismatch or unavailable owner causes a refusal without terminal input or image-byte reads.
This point-in-time query is not an atomic ownership lock.
The feature does not modify zmx, use =zmx send=, or claim input ownership.

If another client owns input, type normally in the intended Session before another paste.
If an old attachment has no marker, reattach it before another image paste.
If the query fails, check the connection and stock zmx support.
The control query retains the existing thirty-second deadline and has no retry.
=C-g= cancels only the owned query.

Stock zmx 0.8.1 replayed the Agent's enabled mode 5522 to a fresh Emacs in the remote checks.
The package sends no synthetic Agent input to enable that mode.
See [[file:remote.org][the remote guide]] for receiver requirements and unconfirmed-delivery handling.

* Sibling Sessions

An Oh My Pi Session that runs in zmx can start a Sibling Session.
Type =/spawn REQUEST= in the Agent.
The Agent picks how much context the new Session gets: none, a fork of its history, a fork with a handoff note, or a handoff summary.
It can start the new Session in another directory or in a new Git worktree on the same host.
Set the omp setting =spawn.confirm= to =true= to confirm each spawn.
The host needs zmx 0.8.1 or later, because omp records the parent link in zmx labels.

omp creates the new Session with =zmx attach= and gives it a name such as =cci-omp-PROJECT-abc123=.
The name keeps the prefix of the parent's zmx name.
omp then writes one announcement to its terminal:

#+begin_src text
ESC ] 52 ; e ; "claude-code-ide-session-spawn-announce" "NAME" ESC \
#+end_src

Ghostel passes the announcement to =claude-code-ide-session-spawn-announce=.
Emacs accepts it only in a live Oh My Pi Session buffer, and only for a name that starts with =claude-code-ide-zmx-session-prefix=.
Emacs then lists zmx on the parent's host and attaches the named Session through the normal attach path.
A remote parent must be on a host in =claude-code-ide-remote-hosts=.
Emacs writes one log line and attaches nothing when the name is not listed, is already attached, or runs an unknown command.

When =claude-code-ide-switch-on-spawn= is non-nil (the default), Emacs switches to the new Session.
Set it to nil to keep the selected window.

Type =/despawn= in the parent to end one of its children.
omp shows one confirmation that names the child, then kills its zmx session.
Emacs then removes the row and closes the buffer, as after Stop.
When the spawn created a Git worktree, =/despawn= applies the omp setting =worktree.onExit= to it.

* Sessions from Outside Programs

An outside program, such as a Session Intake, can ask Emacs to attach a Session that it started in zmx.
It runs =claude-code-ide-adopt-session= through =emacsclient=:

#+begin_src sh
emacsclient --eval '(claude-code-ide-adopt-session "v12dev" "cci-omp-api-x1y2z3")'
emacsclient --eval '(claude-code-ide-adopt-session nil "cci-omp-api-x1y2z3")'
#+end_src

A nil host means the zmx server on the Emacs machine.
A remote host must be in =claude-code-ide-remote-hosts=.
The name must start with =claude-code-ide-zmx-session-prefix=.
The command returns at once and prints one symbol:

- =adopting=: Emacs attaches the Session from a timer, as for a Sibling Session.
- =skipped=: the Session is already live in Emacs, Emacs is already attaching it, or this command attached it before in this Emacs.
- =refused=: the host or the name is not accepted. Emacs shows one message that names the refused value and the Session.

=claude-code-ide-switch-on-spawn= decides whether Emacs switches to the attached Session.

** Pull from a Session Intake

When the Intake cannot reach =emacsclient=, Emacs can pull the Sessions instead.
Turn on =claude-code-ide-intake-mode= after you set these options:

- =claude-code-ide-intake-url=: the Intake base URL, for example =http://127.0.0.1:7311=. When it is nil, pull is off and Emacs never contacts the Intake.
- =claude-code-ide-intake-token-file=: the file with the bearer token. The default is =~/.config/cci-intake/token=. Emacs reads it at each connect.
- =claude-code-ide-intake-client=: the name of this Emacs in the =emacs= entries of the Intake configuration. The default is =(system-name)=, which often differs from that name. The Intake refuses an unknown name, and Emacs shows a message that names this option.

#+begin_src emacs-lisp
(setq claude-code-ide-intake-url "http://127.0.0.1:7311")
(claude-code-ide-intake-mode 1)
#+end_src

Pull needs the =curl= program.
The mode signals an error when =curl= is missing or the URL is nil.
The mode opens the Intake event stream, then reads the running Launches once.
It calls =claude-code-ide-adopt-session= for each running Launch that names a host for this Emacs.
curl reads the token on stdin, so no process argument holds it.
When the stream ends, the mode reconnects after 1, 2, 4, and up to 60 seconds, opens the stream again, and reads the list again.
Push and pull together attach each Session once.
A Session that this command attached once is not adopted again in this Emacs, even after you disconnect it or kill its buffer.
A failed attach does not count, so the next event tries again.
The Intake sends an event on each Agent state change, so without this rule the Session would come back.
To attach it again, use =M-x claude-code-ide-attach=.

** Start the Intake from Emacs

Emacs can start the Intake on this machine, so you need no terminal for it.
Set =claude-code-ide-intake-command= to the program and arguments that start the Intake.
The default is nil, and then Emacs never starts the Intake.
Emacs runs the command in your home directory.

#+begin_src emacs-lisp
(setq claude-code-ide-intake-command
      '("/Users/me/.bun/bin/bun" "run" "/Users/me/agents/cci-intake/src/main.ts"))
#+end_src

The commands:

- =M-x claude-code-ide-intake-start=: start the Intake. Emacs tells you when it answers, when it ended (with the exit code and its last =error:= line), or that it does not answer after 10 seconds.
- =M-x claude-code-ide-intake-stop=: stop the Intake that this Emacs started. Emacs sends =SIGTERM=, and =SIGKILL= after about 5 seconds.
- =M-x claude-code-ide-intake-restart=: stop it, then start it again, for example after you change the Intake configuration.
- =M-x claude-code-ide-intake-log=: show the buffer =*claude-code-ide-intake*=, with all Intake output since the last start.

Rules:

- Emacs never starts a second Intake. Before a start, it checks whether something accepts a connection at =claude-code-ide-intake-url=. Two Intakes on one configuration would start the same Launches twice.
- Emacs starts the Intake only when the URL names this machine: =localhost=, =[::1]=, or an IPv4 address =127.N.N.N=. A host name such as =127.example.com= does not count.
- Emacs stops only an Intake that it started. For an Intake that you started in a terminal or as a service, stop it there.
- When the Intake ends without a stop, Emacs shows one message and does not start it again.
- When you quit Emacs, the Intake that Emacs started stops, without a question. To keep the Intake running while Emacs is closed, start it outside Emacs.

With the command set, =claude-code-ide-intake-mode= starts the Intake when it turns on and nothing answers.
So these lines in your configuration give a working Intake after each Emacs start:

#+begin_src emacs-lisp
(setq claude-code-ide-intake-url "http://127.0.0.1:7311"
      claude-code-ide-intake-command '("/Users/me/.bun/bin/bun" "run" "/Users/me/agents/cci-intake/src/main.ts"))
(claude-code-ide-intake-mode 1)
#+end_src

Turning the mode off does not stop the Intake.
=claude-code-ide-master= and =claude-code-ide-intake-confirm= never start the Intake.

** Master Session

The Master Session is one Oh My Pi Session that you chat with to dispatch work.
It belongs to no project.
It asks the Intake for Launches, and each Launch becomes a Worker Session in its own project.
The Intake sends it a short Notice when a Worker Session ends a turn, ends, fails, or is refused.

This package does not ship the master directory, its =AGENTS.md=, its opening prompt, or its omp command.
You keep them in your own files and in the =[master]= table of the Intake configuration.
The Intake README shows that table and an example =AGENTS.md=.

Setup in Emacs:

1. Set =claude-code-ide-intake-url= and =claude-code-ide-intake-client=, as for pull.
2. Run =M-x claude-code-ide-master=.

The command needs the URL, the =curl= program, and a readable =claude-code-ide-intake-token-file=, and gives an error without them.
It asks the Intake for the one Master Session.
When the Master Session runs and is attached, the command shows it.
Otherwise the command checks the Launch every second, for up to 45 seconds.
When the Launch runs, Emacs attaches it and shows it once.
The command also attaches again a Master Session that you disconnected in this Emacs, so it works after an Emacs restart.
When the Intake cannot be reached, answers with an error, or the Launch fails, the command shows one message and attaches nothing.

Emacs reads two zmx labels that the Intake sets:

- =cci-role=master= marks the Master Session.
  The Session manager shows it under one =Master= heading, before all Project groups.
  A disconnected Master Session row keeps the mark after an Emacs restart.
  A name or a directory never marks a Session.
- =cci-origin=master= marks a Worker Session.
  Emacs attaches it but never moves the focus to it, whatever =claude-code-ide-switch-on-spawn= says.
  So your chat with the Master Session is not interrupted.

When the =[master]= table sets =confirm = true=, the Intake holds each Worker Session Launch until you answer.
With =claude-code-ide-intake-mode= on, Emacs shows one message for each held Launch.
Run =M-x claude-code-ide-intake-confirm=, choose the Launch, read its full prompt, and answer yes to start it or no to refuse it.
The question uses only the minibuffer, so the selected window does not change.

* Detach and Stop

These actions do not mean the same thing:

| Action | Result |
|--------+--------|
| Close the terminal window | Hide the terminal. The client and Agent continue. |
| Kill the terminal buffer | Detach the Emacs client. The Agent continues, and the manager keeps a =[disconnected]= row. Select it or press =c= to reattach. |
| Manager =d= or =M-x claude-code-ide-disconnect= | Close the client and keep a =[disconnected]= row, like a buffer kill. The Agent continues. Refuses a Session that does not run in zmx. |
| Manager =D= or =X= | Detach the client and remove its manager row. The Agent continues. |
| =M-x claude-code-ide-stop= | Ask for confirmation, then kill the zmx Session and Agent for all clients. |
| =zmx kill NAME= | Kill the zmx Session and Agent outside Emacs. |

Use Stop only when every attached client can lose the Agent.

* Existing-Session Safety

Adoption uses this stock zmx command:

#+begin_src text
env -u ZMX_SESSION -u ZMX_SESSION_PREFIX zmx attach NAME false
#+end_src

Stock zmx ignores =false= when =NAME= exists.
If the target disappears before attachment, zmx runs =false= and ends the replacement immediately.
No shell or Agent remains.

The guard can leave one short-lived log file in the zmx log directory.
It does not leave a running process.

* Session Names and Titles

The package uses the Session ID suffix to keep generated names unique.
It sanitizes Agent and project components for zmx names.

Renaming a local zmx-backed Session also updates its zmx =title= label.
The label accepts letters, numbers, periods, underscores, and hyphens.
Other character runs become underscores.

* Environment Limitation

zmx freezes the Agent environment when it creates the Session.
A later client cannot replace MCP or SSE port values in that running process.

After an Emacs restart, port-based integrations can refer to the old Emacs instance.
The terminal remains usable.
Oh My Pi can rediscover the Emacs SSE endpoint and reconnect its selection and state integration.

Start a new zmx Session when another Agent cannot refresh its editor endpoint.

* Troubleshooting

** Emacs cannot find zmx

Check =executable-find= from Emacs.
Set =claude-code-ide-zmx-program= to an absolute executable path when Emacs has a different =PATH=.

** A Session does not appear in an attachment list

Run =zmx list= outside Emacs.
The package excludes a target already attached in the same Emacs instance.
Continue and resume also exclude targets that have clients or lack a client count.

** Bulk attachment skips a Session

Check that =zmx list= reports its start directory and Agent command.
Use =M-x claude-code-ide-attach= when you must supply either value.

** The terminal works but editor integration does not

The running Agent probably has environment values from an older Emacs instance.
Start a new Session unless the Agent supports endpoint rediscovery.

** Stop affects another terminal

This is expected.
Stop kills the zmx Session, not one attach client.
Kill the Emacs terminal buffer when you only want to detach.
